Testing :focus vs :focus-visible

Browsers use their own rules to decide when to show a visible focus indicator. For example, tabbing to a button will usually show a focus ring, while clicking the same button usually will not.

The :focus-visible pseudo-class is based on this browser behaviour. However, the rules are more nuanced than the common explanation of "buttons don't show a ring, text fields do".

These tests set out to find what actually happens, control by control, rather than relying on that shorthand. Each form control was tested three ways:

  1. With no author CSS, to see what the browser does on its own.
  2. With a :focus-visible rule, to see whether an author's rule applies in the same places as the browser's own indicator.
  3. With a :focus rule, to see where it differs from the first two.

Each control was checked twice per variation: once by tabbing to it, and once by clicking it. The overall results are below.

Test page 1: Form controls - browser defaults

Tabbing:

Every control shows a focus ring, with three exceptions, all in Safari on macOS:

  • <input type="range"> shows no ring at all.
  • <input type="color"> can't be reached by Tab.
  • Date-related controls move focus through their individual segments rather than the whole control.

The ring's colour also varies by platform. Chrome on Windows draws a dark ring rather than the blue one used on macOS.

Clicking:

Text fields and date-related controls show a ring. The following controls do not:

  • Buttons: <button>, <input type="button">, <input type="reset">, <input type="submit">, <input type="image">
  • Toggles: <input type="checkbox">, <input type="radio">
  • Others: <input type="color">, <input type="file">, <input type="range">

<select> varies by browser and is covered separately.

Test page 2: Form controls - using :focus-visible

Tabbing:

  • Every control that can be reached by Tab shows the red outline in every browser.
  • This includes Safari's <input type="range">, which gets an outline even though Safari does not draw its own.
  • Safari's <input type="color"> still can't be reached by Tab, so the rule never applies.

Clicking:

  • The results match the browser defaults almost exactly.
  • The same controls show an outline, and the same controls do not.

The main finding is that a :focus-visible rule generally matches the behaviour browsers already use for their own focus styles.

There is one exception: <select> in Chrome on Windows. The browser shows no default ring when it is clicked, but the :focus-visible rule does apply. This is the only difference in the click results, out of 120 comparisons.

Together with Safari's <input type="range"> when tabbing, this shows that a browser's own focus ring and :focus-visible matching are separate decisions. They usually align, but not always.

Test page 3: Form controls - using :focus

Tabbing:

Every control that can be reached by Tab shows the purple outline in every browser, including Safari's <input type="range">.

Clicking:

In Chrome and Firefox, on both platforms, every control except <input type="file"> shows an outline when clicked. This means those controls did receive focus in the earlier tests, but the browser chose not to show a focus indicator.

In Safari on macOS, buttons, checkboxes, radios, submit, reset and image controls show no outline at all. These controls do not receive focus when clicked, which is consistent with Safari's mouse-focus behaviour on macOS.

<input type="file"> shows no outline when clicked in any browser tested. Opening the file picker affects focus, so the :focus outline is not visible during this interaction.

Key findings

Finding 1:

Tabbing and clicking often produce different focus results, as expected.

Finding 2:

The controls that don't show a focus ring when clicked vary slightly between browsers, but generally include:

  • Buttons: <button>, <input type="button">, <input type="reset">, <input type="submit">, <input type="image">
  • Toggles: <input type="checkbox">, <input type="radio">
  • Others: <input type="color">, <input type="file">, <input type="range">

<select> varies between browsers.

The results are almost identical whether you rely on browser defaults or use your own :focus-visible rule, with the one exception covered above.

Finding 3:

If you want focus styles to appear whenever a control receives focus, regardless of whether it was reached by Tab or click, use :focus.

In these tests, :focus showed an indicator in almost every case, with two notable exceptions:

  • <input type="file">, where the indicator is not visible after the file dialog opens.
  • Safari on macOS, where clicking some controls, including buttons, checkboxes and radios, does not give them focus.

Finding 4:

The missing focus ring matters most when clicking a control leaves it focused and ready for further keyboard interaction. Controls such as <input type="checkbox">, <input type="radio">, <input type="range"> and <select> can remain keyboard-operable after a click, even though there may be nothing on screen to show which control has focus.

Finding 5:

<input type="file"> behaves differently from the other controls tested. Clicking it opens the system file dialog and moves focus away from the page. After the dialog closes, no visible focus indicator appears on the input.

This occurred in Chrome, Firefox and Safari, with browser defaults, :focus-visible and :focus, and whether a file was selected or the dialog was cancelled.

What this means in practice

Test focus with the keyboard, not just the mouse. A missing focus ring after a click can be expected behaviour and can happen for different reasons.

When a ring doesn't appear, check whether the control actually has focus rather than assuming the focus style has failed.
